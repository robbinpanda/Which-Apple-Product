1. 评分结论先说清楚

页面显示的是“相对性能指数”，不是某个跑分软件的原始分，也不是 Apple 发布会的倍数。三个指标彼此独立：单核反映短线程响应，多核反映持续并行吞吐，GPU 反映图形/通用计算综合能力。

iPhone 基准A14 Bionic = 100%

iPhone 的单核、多核、GPU 都只与 A14 的同项比较。

iPad / Mac 基准iPad M1 / Mac M1 = 100%

平台分开归一化，避免 iOS 与 macOS 测试环境混为一谈。

固定基准名称直接写在产品表三列标题中。数字用于跨筛选比较；条形只用于快速看出当前结果里同一列的强弱。

2. 公式与权重

所有可比较的原始项先除以同类别基准的对应原始项，得到无量纲比值。然后用加权几何平均合成：

index = 100 × exp( Σ(wᵢ × ln(candidateᵢ / baselineᵢ)) / Σwᵢ )

几何平均有两个好处：不同量纲不会直接相加；单个异常高分对结果的拉动小于算术平均。某个测试确实没有数据时，只在剩余实测项上重新归一化权重，绝不会把缺项当 0 分。

旧 Intel GPU 缺乏贯穿十年的同一 3DMark 子测试，因此主要使用 GB6 OpenCL（有效权重 69.2%）与 FP32（30.8%）重新归一化；这比混用 3DMark 11、Fire Strike、Time Spy 的不可比数字更严谨。

条形长度为什么与百分比不是同一把尺

百分比数字始终使用上面的固定基准，排序、规格弹窗和并排对比也都读取这个数字。条形是辅助视觉，单核、多核、GPU 分别使用当前可见结果的列最大值归一化：

bar_width = score / max(score in current visible column) × 100%

因此即使 GPU 最高为 450%、单核最高为 190%，两列冠军都会各自显示满格；筛选或切换芯片后重新计算。条形只能在同一列内比较，不能拿不同列的长度互相比；固定在 25% 的旧基准线已经删除。

3. 数据不是只参考 NanoReview

NanoReview 适合快速获得同版本 Geekbench、Cinebench、PassMark、Blender、3DMark 与理论值的聚合入口，但它的“Final Score”算法并不透明，所以本站不采用那个总分。我们提取可核对的测试项，再与原始平台或第二来源交叉检查。

NanoReview CPU / SoC多项公开跑分聚合与芯片规格；不用其最终总分 NanoReview GPUGB Compute、3DMark、Blender 与 FP32 聚合入口 Geekbench Browser · Mac具体 Mac 型号与处理器的大样本 GB6 聚合 Geekbench Browser · OpenCLIntel / AMD / Apple GPU 的同版本计算测试 PassMark老 Intel 的大样本跨代校准；因平台差异只给低权重 Cinebench 2024Mac 持续 CPU 渲染交叉验证；仅采用版本一致的值 Apple 技术规格合法芯片、容量、屏幕、重量、电池和接口的唯一主口径 UL 3DMark只在测试项目和版本一致时进入 GPU 合成

这里的“公开数据”表示可公开访问和复核，并不宣称这些网站内容具有开源软件许可证。

4. 某个芯片没有独立跑分页，怎么办？

4.1 同架构降配 GPU

例如 M1 Pro 10CPU/14GPU、M1 Max 10CPU/24GPU 或 MacBook Air 的少核心 GPU，经常没有稳定的独立聚合页。处理顺序是：

  1. 先找具体机型 / 具体核心档的 Geekbench Browser 聚合；
  2. 再找相邻核心档的 GB Compute、3DMark 或设备实测；
  3. 仍缺项时，以同架构满血档为锚，按官方核心数比例并使用跨档实测拟合的 比例^0.93 缩放实际 GPU 项，FP32 仍按核心比例；
  4. 所有合成分继续由同一公式实时算出，绝不直接手写“约 180%”。

4.2 少 CPU 核心档

单核保持同代实测；多核使用相邻档实测优先。没有精确聚合时，按性能核心数量与同机型功耗档校准，不能只按总核心数线性相乘。M4/M5 iPad Pro 的 9 核/10 核档以及 M1 Pro 8 核/10 核档都按这个原则处理。

4.3 老 Intel 与 AMD

2016–2020 Mac 优先采用对应 Mac 型号的 Geekbench 6 聚合，而不是只看同名 CPU 的 Windows 机器。PassMark 仍有实测时用于校准；Cinebench 2024 没有覆盖就对 GB6 + PassMark 权重重新归一化。GPU 使用同版本 OpenCL 与 FP32，Radeon Pro 档位按具体独显区分。

因此产品页上的每一个芯片 / GPU 档位都有单核、多核和 GPU 百分比；“估算”发生在缺失的原始测试项，不是凭感觉编一个最终百分比。

6. 产品官方规格口径

机型范围按首次发布年份纳入 2016–2026。芯片、官方选配、存储、屏幕、分辨率、刷新率、重量、电池、接口和外接显示器来自每行直达的 Apple 技术规格页。

  • Apple 未写刷新率时显示“Apple 未标注 Hz”，不把常识伪装成官网数据；早期 iPad Pro 只写 ProMotion 时也不补一个数字。
  • Apple 不公开 iPhone 额定 Wh，因此显示官方最长视频 / 流媒体时长；iPad 与 Mac 官网公开 Wh 时才展示容量。
  • 内存与存储使用一个“目标规格组合”选择器，只列当前芯片档的合法搭配；相同芯片下的绑定配置会合并展示，不生成重复芯片项。
  • iPad Pro 的容量—内存—CPU 档绑定为不可拆选项；例如 M1/M2 的 8GB + 128/256/512GB 与 16GB + 1/2TB 分开列出，M4/M5 切到高容量档还会同步切换对应 CPU。
  • M2–M5 Pro / Max 的内存和存储按具体芯片档分别声明，不用一个过宽数组拼出假组合。例如 M5 Pro 仅 1–4TB，M5 Max 仅 2–8TB；32 核 GPU M5 Max 只列 36GB。

7. 闲鱼 / 转转价格审计与新模型

审计结论：旧价格不能继续使用。117 款基础数据中的转转中点平均是闲鱼的 85.08%；34/34 款 iPad 与 43/43 款 Mac 的两端几乎都等于“闲鱼 × 0.85（±10 元）”，说明它不是独立平台样本。旧配置公式还让 28 个芯片组重复叠加绑定内存 / 存储，1,273 个合法配置中有 8 个出现 0 元端点。

7.1 两个平台现在分别代表什么

  • 闲鱼个人：普通个人自用机的挂牌与近期成交估值。
  • 转转验机：买家购买带验机、退货或质保服务商品的零售估值；页面以“≈”明确它是模型值。
  • 平台回收：卖给平台的买断报价，通常显著低于买家零售价，已从本站排除。旧版把较低的数值配到转转购买搜索链接，是语义错误。

统一机况为：无激活锁 / 监管锁，无重大拆修和功能故障，屏幕完整，电池通常不低于约 85%。故障机、资源机、扩容机、配件打包价和极端成色不进入正常区间。转转官方验的服务属性可见其官方验说明。

7.2 样本怎样收集

闲鱼和转转网页版均有登录墙与动态加载，无法在不登录的情况下复现完整结果页。因此本次没有声称“全站抓取”，而是采用可公开复核、明确写出配置与价格的近期交易帖、带闲鱼分享链接的卖帖、已售补充、公开零售页和平台回收实测；挂牌与成交不混为同一种证据。

7.3 有直接样本与没有直接样本时怎么计算

  1. 直接 SKU 锚点优先：本轮为 28 个高代表性默认配置建立 2026-08 锚点区间，包括 iPhone 13/14/15/16 Pro、iPad Air 5、M1/M4 iPad Pro、M1/M2/M3/M4/M5 MacBook 常见档。
  2. 同系列插值：没有直接锚点的默认配置，使用同类别、同系列（如 Pro 14、Air、iPhone Pro）的锚点校准倍率；按与目标年份的距离加权。只有一个同系列锚点时，以 65% 同系列 + 35% 同类别锚点混合，避免单样本外推十年。
  3. 配置只从本芯片组锚点算：芯片档的整包差价与该芯片组内部的内存 / 存储差价分开；切到本身就绑定 32GB 或 1TB 的 Max / iPad Pro 档时，不会再对基础机的 16GB / 512GB 重复收费。
used_bundle_delta = bundle_delta × retention(age)
used_pair_delta = within_group_component_delta × min(78%, 1.5 × retention)
selected_mid = audited_base_mid + used_bundle_delta + used_pair_delta

机龄 0–10 年的整包差价保留率依次为 62%、55%、48%、42%、38%、34%、29%、25%、21%、18%、15%。旧 Intel 高配的总上浮另限制在默认中点的 90% 内，2021–2022 为 140%，更新机型为 180%；低配最多下调默认中点的 65%。这不是在宣称稀有 CTO 一定成交于该价，而是阻止 2019 年 8TB 机器仍完整保留当年新机选配价。

区间在“中点 + 相对离散率”上生成，而不是给上下限同时加一个固定金额再截成 0；稀有高配不会因为价格更高而显得虚假地更精确。所有端点按 50 元取整且必须大于 0。

7.4 转转为什么高于闲鱼，是否仍是机械值？

转转官方验是带平台服务的买家零售，不是回收，因此方向上应高于同条件个人 C2C。缺少可复核的同 SKU 独立样本时，页面明确显示为估值：以闲鱼中点增加 iPhone 10%、iPad 11%、Mac 12% 的服务溢价，再使用较窄但仍重叠的区间。这个 10%–12% 是当前的跨平台模型参数，不会被描述成“转转实测价”；有足够独立零售样本后应由各 SKU 直接区间替换。

8. 交叉验证、异常值和边界

同一芯片可能因系统版本、散热、功耗和样本结构出现波动。处理规则：

  1. 只比较同一主版本的 benchmark；
  2. 优先设备聚合或中位区间，不采用单条最高成绩；
  3. 某来源的相对值偏离其他来源中位数约 18% 以上，先核查测试版本和 API；确认异常后降权或隔离；
  4. 理论 FLOPS 不直接等同游戏帧率，权重始终低于实测；
  5. 评分保留整数百分比展示，内部计算不提前取整。

百分比适合做同类别硬件层级比较，不等于所有 App 都会按同一倍数加速，也不能代替内存容量、媒体引擎、光追、显示器支持和散热差异。二手价格同样只是普通机况估值，稀有配置、AC+、地区版本与电池状态会造成额外偏差。

数据快照：2026-08-17。后续更新跑分时应保留基准芯片和权重不变；价格更新则应保留原样本日期与配置，并优先用新的同 SKU 独立平台样本替换模型值。
